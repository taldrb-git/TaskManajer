# ארכיטקטורה

## סקירה

אפליקציה סטטית (SPA) ללא שרת משלה. היא בנויה על עיקרון **local-first**: כל הפעולות מתבצעות קודם על נתונים מקומיים בדפדפן,
ו-Supabase הוא שכבת סנכרון אופציונלית.

```
 דפדפן / PWA                                     Supabase (אופציונלי)
┌───────────────────────────────────┐            ┌─────────────────────────┐
│ React UI (App.tsx, components/)   │            │ Auth (דוא"ל + סיסמה)    │
│        │  useStore()              │            │ Postgres: lists, tasks  │
│        ▼                          │  upsert    │   + RLS לפי user_id     │
│ store.ts ── localStorage          │ ─────────► │   + trigger             │
│   │ תור שינויים (dirty)           │ ◄───────── │     server_updated_at   │
│   └ מנוע סנכרון                   │  select    │ Realtime ───────────────┼─► התראה על שינוי
│ Service worker (Workbox) – offline│            └─────────────────────────┘
└───────────────────────────────────┘
        אירוח סטטי: GitHub Pages
```

## פענוח הוספה מהירה (`parseQuickAdd`)

הפונקציה מקבלת טקסט חופשי, מהמקלדת או מזיהוי הדיבור, ומחזירה `{ title, due?, priority? }`.

**ניקוי מקדים (`normalizeSpoken`):** לפני הזיהוי הטקסט מנוקה:
- מוסרים סימני כיוון (U+200E, U+200F, U+202A–U+202E, U+2066–U+2069). Chrome מוסיף אותם לטקסט עברי מזיהוי דיבור.
- רווחים מיוחדים הופכים לרווח רגיל, ומקף עברי (U+05BE) ומקפים ארוכים הופכים ל-`-`.
- מספר במילים בין 1 ל-31 (זכר ונקבה, כמו "עשרים וחמישה" או "שלוש עשרה") מומר לספרות.
  ההמרה קורית רק כשאחריו בא "לחודש", "בחודש" או שם של חודש, כדי לא לשנות כותרות כמו "לקנות שלושה תפוחים".

**התאריך:** נבחר הדפוס הראשון שמתאים, לפי הסדר הזה:
1. מספרי: `25.11` או `25/11/2026`.
2. חודש במילים: `25 בנובמבר`.
3. יום בחודש בלי שם חודש: `ב-25 לחודש (הבא)`. מחושב ב-`makeDayOfMonth`: החודש הנוכחי, ואם עבר, החודש הבא. אם אין יום כזה בחודש (31 בחודש של 30 יום), עוברים לחודש הבא.
4. `בעוד N ימים / יומיים / שבוע / שבועיים`.
5. יום בשבוע: `ביום שלישי (הקרוב/הבא)` או `בשבת`. התוצאה היא המופע הבא, לא היום עצמו.
6. `מחרתיים`, `מחר`, `היום`.

כמה כללים נוספים:
- `makeDate` פוסל תאריכים לא תקינים. תאריך בלי שנה שכבר עבר עובר לשנה הבאה.
- הקידומות `ב`, `ל`, `עד`, `ה-` ומקף לפני התאריך נבלעות בו.
- אחרי זיהוי התאריך מוסרים סימני העדיפות `!` ומילות הפתיחה (`FILLER`, למשל "יש לי" או "תזכיר לי").

ביטויים רגולריים שנבנים עם `new RegExp` משתמשים ב-`String.raw`, כדי שלוכסן אחורי (`\s`, `\d`) לא יאבד בתוך תבנית טקסט (template literal).

## זיהוי דיבור (`speech.ts`)

- **הממשק:** `SpeechRecognition` או `webkitSpeechRecognition`, עם `lang = 'he-IL'`, `interimResults = true` ו-`continuous = false`.
  הקלטה אחת לכל לחיצה.
- **הזרימה:** הטקסט, גם הזמני, נכתב לשורת הקלט. ההוספה עצמה דורשת לחיצה על החץ, כדי שאפשר יהיה לבדוק ולתקן לפני השמירה.
- **שגיאות** (הרשאה, אין דיבור, אין רשת) מתורגמות לעברית ומוצגות בחלונית.
- **מגבלות:**
  - דורש הקשר מאובטח (HTTPS או localhost) וחיבור לאינטרנט.
  - הקול מעובד בשרתים של ספק הדפדפן.
  - בדפדפן בלי תמיכה הכפתור מוסתר.

## שכפול (`duplicateTask`)

`duplicateTask(id, count, { everyDays, numbered })`. בממשק יש שני מצבים: "מספר פעמים", ו"עד תאריך" שבו
`count = floor(diffDays(start, until) / everyDays) + 1` (עד 365). אם יוצא פחות מ-2, כפתור היצירה מושבת.

- יוצרת `count - 1` עותקים בתאריכים `start + (i-1)·everyDays`. `start` הוא תאריך המשימה, או היום אם אין לה תאריך.
- העותקים מקבלים את `priority`, `list_id` ו-`notes` של המקורית.
- עם `numbered` הכותרות הופכות ל-"`<כותרת> i`", וגם המקורית מקבלת 1.
- הפונקציה מחזירה פונקציית ביטול, שמוחקת (מחיקה רכה) את העותקים ומחזירה את הכותרת והתאריך המקוריים.
- מצב השכפול מוצג בתוך אותו `Sheet` של העריכה. חלון חדש היה מפעיל את `useDismiss` מחדש, וה-`history.back()` האסינכרוני היה סוגר אותו מיד.

### חלונות מעל המקלדת
- באייפון, רכיב `position: fixed` נשאר מאחורי המקלדת, כי המקלדת מקטינה רק את ה-`visualViewport` ולא את החלון.
- `useKeyboardViewport` מאזין ל-`resize` ול-`scroll` של `visualViewport`. כשהמקלדת פתוחה (הפרש של 80px ומעלה), הוא מחזיר `top` ו-`height` לרקע של `Composer` ושל `Sheet`, כך שהחלון יושב בדיוק באזור הנראה.
- במובייל `.sheet-backdrop` הוא flex בעמודה, ול-`.sheet` יש `max-height: min(92dvh, 100%)`, כדי שחלון העריכה יתכווץ לגובה שנשאר.

## כיווץ לוח השנה

- ל-`Calendar` יש שני מצבים:
  - **מורחב:** החודש של `anchor`.
  - **מכווץ:** השבוע (ראשון עד שבת) של `anchor`.
- `anchor` מתעדכן ליום הנבחר בכל בחירה. החצים מזיזים אותו בחודש או בשבוע.
- **החלקות:** אנכית מעל 40px מכווצת (למעלה) או מרחיבה (למטה). אופקית מעל 50px עוברת לחודש או לשבוע הקודם או הבא.
  ללוח יש `touch-action: none`, כך שההחלקות עליו לא גוללות את הדף.
- המצב נשמר ב-localStorage במפתח `task-manager:calendar-collapsed`.

## גרירה לתאריך (`useDateDrag`)

- **יעדי שחרור:** כל אלמנט עם `data-date="YYYY-MM-DD"`. כרגע אלה ימים בלוח השנה (`.cal-day`) וקבוצות תאריך במסך "בקרוב" (`.section`).
  היעד מזוהה בעזרת `elementFromPoint` ו-`closest('[data-date]')`. לתצוגה הצפה יש `pointer-events: none`, כדי שלא תסתיר את היעד.
- **עכבר:** הגרירה מתחילה אחרי תזוזה של 6px.
- **מגע:** הגרירה מתחילה אחרי לחיצה ארוכה של 350ms. אם האצבע זזה יותר מ-8px לפני כן, זו גלילה והגרירה מתבטלת.
  אחרי שהגרירה התחילה, `touchmove` (שנרשם עם `passive: false`) מונע גלילה.
- **אחרי שחרור:** הקליק שמגיע אחרי השחרור נחסם (`onClickCapture`), כדי שחלון העריכה לא ייפתח.
- **הפעלה:** הגרירה פעילה רק במסכים "לוח שנה" ו"בקרוב", ורק למשימות פתוחות.
  ההעברה עצמה היא `updateTask(id, { due })` עם הודעת ביטול. `postponed` לא משתנה.

## משימות חוזרות

- `toggleTask(id)` מחזיר פונקציית ביטול.
- כשמסמנים משימה עם `repeat`:
  1. נוצרת משימה חדשה עם `due = nextOccurrence(due, repeat)`. היא מקבלת את אותם כותרת, שעה, תזכורת, עדיפות, רשימה והערות, ותת-משימות לא מסומנות.
  2. `repeat` עובר מהמשימה שהושלמה אל החדשה. ככה הסדרה ממשיכה רק מהמשימה הפתוחה האחרונה.
- **ביטול:** מוחק לצמיתות (`purgeTask`) את המשימה החדשה ומחזיר את `repeat` למקורית.
- `nextOccurrence`:
  - `weekdays` מדלג על שישי ושבת.
  - `monthly` ו-`yearly` נצמדים לסוף החודש כשאין בו את אותו יום (31 → 30, 29 בפברואר → 28).

## סל מחזור

- `deleteTask` מסמן `deleted = true` ו-`deleted_at = now`.
- `snapshot.trash` מכיל את המשימות שנמחקו ב-30 הימים האחרונים.
- `purgeTask` מציב ב-`deleted_at` את הערך `1970-01-01`. ככה המשימה יוצאת מטווח הסל בכל המכשירים, והמחיקה עדיין מסתנכרנת כרשומה רגילה.
- `restoreTask` מאפס את שני השדות.

## תזכורות (`reminders.ts`)

- `reminderAt(t) = due + time − remind דקות`.
- `App` קורא ל-`checkReminders(tasks)` בכל שינוי ובכל 30 שניות.
- **ההתראה:** דרך `serviceWorker.showNotification`, ואם אין service worker, דרך `new Notification`.
- **מניעת כפילות:** כל תזכורת שנשלחה נשמרת ב-localStorage במפתח `task-manager:reminded`, לפי `id@זמן`.
  לכן אם משנים את השעה, נשלחת תזכורת חדשה.
- תזכורת שאיחרה ביותר משעה לא נשלחת.
- **מגבלה:** התזכורות עובדות רק כשהעמוד חי, גם ברקע. כדי לקבל אותן כשהאפליקציה סגורה צריך Web Push משרת
  (למשל Supabase Edge Function עם cron ו-VAPID). זה מתוכנן לשלב הפריסה.

## חגים (`holidays.ts`)

- היום והחודש העבריים מחושבים עם `Intl.DateTimeFormat('en-u-ca-hebrew')`, שנותן שמות חודשים יציבים באנגלית לחישוב.
  לתצוגה משתמשים ב-`he-IL-u-ca-hebrew`.
- `Intl` מחזיר ספרות רגילות, ולכן `gematria` ממיר את היום והשנה לאותיות, כולל ט״ו/ט״ז וגרשיים.
- **חגים קבועים:** לפי יום וחודש עבריים. בשנה מעוברת פורים הוא ב-Adar II.
- **הזזות:**
  - יום השואה: אם כ״ז בניסן יוצא בשישי, עובר לחמישי. אם בראשון, עובר לשני.
  - יום העצמאות: אם ה׳ באייר יוצא בשישי או בשבת, עובר לחמישי. אם בשני, עובר לשלישי. יום הזיכרון הוא יום לפני.
  - צום גדליה, תענית אסתר, י״ז בתמוז ותשעה באב נדחים או מוקדמים כשהם יוצאים בשבת.
  - חנוכה: שמונה ימים מכ״ה בכסלו.
- התוצאות נשמרות במטמון (`Map`) לפי תאריך.

## החלקה (`TaskItem`)

- **זיהוי:** ב-`touchmove`, אם התזוזה האופקית גדולה מ-12px ומ-1.5 כפול התזוזה האנכית, זו החלקה.
  אם התזוזה האנכית מעל 10px, זו גלילה ולא קורה כלום.
- לשורה יש `touch-action: pan-y`, כך שהדפדפן מטפל רק בגלילה אנכית ולא צריך `preventDefault`.
- **הפעלה:** החל מ-90px. שמאלה מפעיל את `onPostpone`, שקורא ל-`postponeTask` (יום קדימה ו-`postponed + 1`).
  ימינה תלוי ב-prop `swipeRight`: `'done'` (ברירת מחדל) מפעיל את `onToggle`, ו-`'delete'` (במסך "היום" ובלוח השנה) מפעיל את `onDelete`. ב-App זה `onSwipeDelete`: `deleteTask` ואחריו הודעה עם ביטול (`restoreTask`).
- **יחד עם הגרירה:** האירוע `onTouchStart` מועבר גם ל-`useDateDrag`. הגרירה מתבטלת לבד כשיש תזוזה של יותר מ-8px לפני הלחיצה הארוכה, ולכן שתי המחוות לא מתנגשות.

## גרף הסיכום

- גרף עמודות של סדרה אחת, בלי מקרא, כי הכותרת מתארת אותו.
- **צבע:** `--chart`, גוון עמוק יותר של צבע ההדגשה. הגוונים הבהירים של צבעי ההדגשה לא עוברים את בדיקת הבהירות על הרקע הכהה.
  הגוונים העמוקים נבדקו עם `validate_palette.js` מול הרקע `#1c1f27`.
- **עמודות:** קצה עליון מעוגל 4px, ורווח של 2px ביניהן.
- נגיעה או מעבר עם העכבר מציגים tooltip עם המספר והתאריך.
- יש גם טבלה נסתרת (`sr-only`) לקוראי מסך.

## גלגול בחצות (`rollover`)

כל משימה שעומדת בכל התנאים האלה עוברת להיום:
- היא לא הושלמה ולא נמחקה.
- יש לה `due`.
- `due` מוקדם מהיום.

בזמן הגלגול `postponed` גדל ב-`diffDays(due, today)`, ו-`updated_at` מתעדכן. הרשומה נכנסת לתור הסנכרון.

**מתי הגלגול רץ:**
- בטעינת המודול.
- בטיימר שמכוון ל-00:00:05 ומתוזמן מחדש אחרי כל ריצה.
- ב-`visibilitychange`, כי טלפונים מקפיאים טיימרים כשהאפליקציה ברקע.
- בסוף כל סבב סנכרון, למקרה שהגיעה רשומה ממכשיר שעוד לא גלגל.

אם התאריך התחלף, הגלגול קורא ל-`emit()` גם כשלא זזה אף משימה, כדי שהתוויות במסך ("היום", "מחר") יתעדכנו.

**שני מכשירים** שמגלגלים את אותה משימה מחשבים את אותה תוצאה, כי החישוב מבוסס על `due` ו-`postponed` של הרשומה.
לכן ההכרעה לפי last-write-wins לא יוצרת סתירה.

## הסנכרון

**שמירה מקומית:** כל פעולה עוברת דרך `commit()`, שמבצעת:
1. עדכון של הרשומה בזיכרון ושמירה ב-localStorage.
2. הוספת המזהה לתור `dirty[table]`.
3. עדכון של React דרך `useSyncExternalStore`.
4. תזמון סנכרון 700ms אחר כך. שינויים קרובים מצטברים לסנכרון אחד.

**סבב סנכרון (`syncNow`):**
1. **push:** שליחת הרשימות ואז המשימות מהתור ב-`upsert` (בקבוצות של 500).
   מזהה יוצא מהתור רק אם `updated_at` שלו לא השתנה בזמן השליחה.
2. **pull:** שליפת רשומות עם `server_updated_at >= cursor`, ממוינות ובדפים של 1000.
   משתמשים ב-`>=` כדי לא לפספס רשומות עם אותה חותמת זמן. קבלה כפולה של רשומה לא מזיקה.
3. **הכרעה (last-write-wins):** אם לרשומה יש שינוי מקומי שעוד לא נשלח וה-`updated_at` המקומי חדש יותר, נשארת הגרסה המקומית.
   בכל מקרה אחר נכנסת הגרסה מהשרת.

**מתי מסתנכרנים:** אחרי שינוי, כשהרשת חוזרת (`online`), כשחוזרים ללשונית, כל 60 שניות,
וכש-Supabase Realtime מודיע על שינוי בטבלאות של המשתמש.

**התחברות והתנתקות:**
- משימות שנוצרו לפני ההתחברות נמצאות כבר בתור, ולכן עולות לחשבון.
- אם מתחבר במכשיר משתמש אחר מזה שהיה מחובר קודם, הנתונים המקומיים מתאפסים כדי לא לערבב בין חשבונות.
- בהתנתקות האפליקציה מסנכרנת, מתנתקת ומוחקת את הנתונים מהמכשיר.

**בין לשוניות:** האירוע `storage` טוען מחדש את הנתונים כשלשונית אחרת שינתה אותם.

## החלטות ומגבלות ידועות

- **localStorage:** מוגבל לכ-5MB, שזה אלפי משימות. אם יהיה צורך ביותר, אפשר לעבור ל-IndexedDB בתוך `store.ts` בלבד.
- **אין מצב "באיחור" בפועל:** הקוד של המקטע "באיחור" והנקודה האדומה בלוח נשאר. הוא נראה רק בפרק הזמן הקצר שבין חצות לגלגול.
- **מחיקות רכות לא מנוקות:** רשומות שנמחקו נשארות (`deleted = true`) ולא מוצגות.
- **הכרעה לפי שעון הלקוח:** אם השעון במכשיר שגוי מאוד, זה יכול להשפיע על איזה שינוי ינצח.
- **התחברות בדוא"ל וסיסמה ולא בקישור קסם:** ב-PWA מותקן באייפון, קישור במייל נפתח ב-Safari ולא באפליקציה.
- **בלי `StrictMode`:** הוא מריץ effects פעמיים, וזה שובר את הטיפול בכפתור "חזור" ב-`Sheet`
  (`pushState` ואז `history.back()` אסינכרוני).
- **`uid()` עם גיבוי:** `crypto.randomUUID` זמין רק ב-HTTPS או ב-localhost, ולכן יש גיבוי למקרה של גישה מהטלפון דרך IP ברשת המקומית.
